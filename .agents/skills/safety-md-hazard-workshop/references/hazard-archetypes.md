# Hazard archetypes

Apply every family. Mark not applicable only with a reason.

| Family | Questions |
|---|---|
| Patient identity | Could the wrong patient/context/record be selected, matched, merged, or displayed? |
| Calculation / algorithm | Could an equation, threshold, rounding rule, unit, or logic path produce a harmful output? |
| Data freshness | Could stale, delayed, cached, or unsynchronised data affect care? |
| Data integrity | Could data be corrupted, truncated, duplicated, silently overwritten, or mis-coded? |
| Interoperability | Could an API/interface/terminology mapping failure cause missing or wrong clinical information? |
| Access to information | Could clinicians be unable to access necessary information at the point of care? |
| Alerts / notifications | Could urgent information fail to alert, over-alert, alert the wrong person, or be ignored? |
| Workflow mismatch | Could the product encourage unsafe workflow, handoff, responsibility, or escalation patterns? |
| Usability / misuse | Could reasonable users misunderstand, misuse, overtrust, or bypass the product? |
| Configuration | Could local settings, thresholds, roles, formularies, or feature flags create unsafe behaviour? |
| Downtime / degraded mode | Could outage, partial outage, failover, or fallback behaviour harm patients? |
| Auditability | Could inability to reconstruct clinical decisions impede safety investigation or correction? |
| Security-as-safety | Could confidentiality, integrity, or availability failures create patient harm? |
| Data migration | Could migration/import/export lose, duplicate, or misclassify clinical data? |
| Secondary use / analytics | Could research, analytics, dashboards, or derived data feed back into care unsafely? |
| AI/ML | Could model bias, drift, opacity, poor calibration, or automation bias affect care? |
| Decommissioning | Could retirement/replacement remove access, break continuity, or lose safety evidence? |
